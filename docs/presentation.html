a11yFixer

One Jira parent in.
Twelve draft PRs out.

A ~2,000-line Node/TypeScript harness with zero runtime dependencies. It shells out to the claude CLI, git and gh. That's the whole stack.

parent Jira issue → direct subtasks → per subtask: worktree · fetch ticket · bootstrap · implement · verify · review · draft PR

part 1 · the core mechanism

Context isolation is one CLI flag

src/claude.ts — every model call
// no --resume  →  brand new context
runClaude({ prompt, cwd })

// with --resume →  same context continues
runClaude({ prompt, cwd, resume: sessionId })
There is no session manager, no state machine, no cleanup. The presence or absence of one argv flag is the entire isolation guarantee.

Per subtask, five distinct contexts:

fetch ticket fresh → dies bootstrap ─┐ implement │ one, resumed repair ─┘ → dies claim Jira fresh → dies review fresh → dies PR metadata fresh → dies

5 contexts · 6–7 process spawns

part 1 · the trust boundary

Agents read and edit. The harness does everything irreversible.

src/claude.ts 12–13
export const READ_ONLY_TOOLS =
  ["Bash", "Edit", "Write", "NotebookEdit"];

export const EDIT_NO_SHELL_TOOLS =
  ["Bash", "NotebookEdit"];

passed as --disallowed-tools

  • The implementer gets EDIT_NO_SHELL_TOOLS — it can edit files, Bash is denied
  • Reviewer, PR-prep and all Jira agents get READ_ONLY_TOOLS
  • worktree, branch, test execution, commit, push, PR — all in the harness
The agent can never tell me a test passed. I run it and read the exit code.

part 2 · 1 of 13

parseArgs — pure, no I/O

src/cli.ts 31
for (let i = 0; i < argv.length; i++) {
  const a = (argv[i] as string).trim();
  // A stray backslash or pasted shell decoration produces empty args; ignore rather than choke.
  if (a === "" || a === "\\") continue;
  if (a === "--repo") repo = (argv[++i] ?? "").trim();
  else if (a === "--model") model = (argv[++i] ?? "").trim() || null;
  else if (a === "--dry-run") dryRun = true;
  else if (a === "--jira-tool") jiraTool = (argv[++i] ?? "").trim();
  else if (a.startsWith("--")) throw new Error(`unknown flag: ${a}`);
  else if (!parentUrl) parentUrl = a;
  else throw new Error(`unexpected argument: "${a}" …`);
}
No argument-parsing library. Pure in, pure out, so it is trivially unit tested — and it is, heavily. Nothing has touched the filesystem yet.

Captured once, never re-read. Twelve worktrees are all created from this SHA, so no subtask's changes can appear in another's diff or PR.

part 2 · 5 of 13

runClaude — the only path to a model

src/claude.ts 67
const args = ["-p", "--output-format", "json", "--permission-mode", "bypassPermissions"];

if (call.resume)                args.push("--resume", call.resume);
if (call.model)                 args.push("--model", call.model);
if (call.disallowedTools?.length) args.push("--disallowed-tools", ...call.disallowedTools);
if (call.addDirs?.length)       args.push("--add-dir", ...call.addDirs);
if (call.jsonSchema)            args.push("--json-schema", JSON.stringify(call.jsonSchema));

const res = await exec("claude", args, {
  cwd: call.cwd,
  timeoutMs: call.timeoutMs ?? DEFAULT_TIMEOUT_MS,
  // The prompt goes over stdin so large diffs never hit argv limits.
  stdin: call.prompt,
});
  • stdin, not argv — a 200 KB diff would blow ARG_MAX
  • --json-schema forces structured output — no regex-parsing of prose
  • --resume present or absent — the isolation decision, made per call

Reading the response

src/claude.ts 88
const parsed = JSON.parse(res.stdout);

const text = typeof parsed["result"] === "string" ? parsed["result"] : "";
const structured =
  parsed["structured_output"] != null
    ? parsed["structured_output"]
    : extractJson(text);            // fallback: scrape a JSON object out of prose

return {
  sessionId: String(parsed["session_id"] ?? ""),   // ← what --resume needs next time
  text, structured,
  isError: parsed["is_error"] === true || parsed["subtype"] !== "success",
  raw: res.stdout,
  usage: parseUsage(parsed),        // tokens, cost, context %
};
sessionId is the handle. Store it and pass it back as resume to continue a context; drop it to end that context forever.

part 2 · 7 of 13

The loop, and the only shared state

src/cli.ts 188
const ctx: RunContext = {
  repoPath: repo,
  baseSha, baseBranch, runDir,
  model: args.model,
  dryRun: args.dryRun,
  jiraTool, jiraAccount,
};

for (const subtask of discovery.subtasks) {
  if (isAlreadyDone(subtask.status)) { … continue; }
  try   { outcomes.push(await runSubtask(ctx, subtask)); }
  catch { outcomes.push({ kind: "failed", … }); }
}
RunContext is paths and strings. No model state crosses the loop boundary — that is the isolation guarantee, enforced by the type.
  • Sequential by design — no concurrency in v0
  • try/catch per iteration: one bad subtask never kills the run

part 2 · 8 of 13

runSubtask — setup and the failure path

src/worker.ts 105
export async function runSubtask(ctx: RunContext, subtask: Subtask): Promise<Outcome> {
  const worktree  = path.join(ctx.runDir, subtask.key, "worktree");
  const artifacts = path.join(ctx.runDir, subtask.key, "artifacts");
  let usage = emptyUsage();

  const fail = (reason: string, branch: string | null, verdict?: Verdict): Outcome => {
    stopSpinner();
    detail(`worktree preserved: ${worktree}`);
    return { kind: "failed", subtask, reason, branch, worktree, verdict, usage };
  };
fail() returns an Outcome — it never throws. Throwing is reserved for harness bugs, which the loop's catch handles. Two error channels, deliberately separated.
